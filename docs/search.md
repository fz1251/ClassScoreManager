# 拼音搜索与导航窗格

> 本文记录左侧导航窗格的搜索范围、拼音匹配算法、字典数据与维护方式。主索引见 [README.md](README.md)。

## 1. 结构

- `MainWindow` 持有唯一的 `SearchPane` 和唯一的 `SearchListModel`。
- 中央区用 `QSplitter` 分隔搜索窗格与主 `QStackedWidget`；这是界面中唯一可拖动的分栏。
- 窗格不感知页面。`MainWindow` 根据 `QStackedWidget::currentIndex()` 映射 `SearchScope`，切换模型的数据源、窗格标题与空状态文字。
- 程序不为窗格提供菜单项。`Ctrl+F` 在任意页面打开窗格；学生页“学生操作”的“搜索学生”、记录页与模板页工具栏的“搜索”也提供入口。窗格已打开时只把焦点交给搜索框并全选，不清空查询；关闭用窗格右上角的关闭按钮。
- 学生页和小组页共用 `SearchScope::Student`：两页之间切换时，查询、结果、选中项和滚动位置都保留，只有结果激活的目标不同（表格行 / 小组卡片）。
- 切换到另一范围时清空查询，模型按新范围重建条目；只有非空查询才运行匹配。

| 页面 | 范围 | 搜索对象 | 激活结果 |
| --- | --- | --- | --- |
| 学生信息 | `Student` | 学生姓名 | 选中表格行并滚动到中央 |
| 小组管理 | `Student` | 学生姓名 | 滚动到卡片并播放入场动画 |
| 积分记录 | `Record` | 记录描述 | 选中列表行并滚动到中央 |
| 积分模板 | `Template` | 模板名称 | 选中列表行并滚动到中央 |
| 欢迎页 | 无 | 窗格隐藏 | — |

窗格内只有一个 `QLineEdit`、一个 `QListView` 和一个模型；范围切换不替换控件。内部 `QStackedWidget` 只用于“结果列表 / 空状态”二选一，不是三套搜索页。

## 2. 匹配算法

拼音搜索不在查询期生成读音组合串，而是在“读音格”上运行 ε-NFA 做子串可达性判定。

### 2.1 文本 token 与写法

| 文本片段 | 可用写法 |
| --- | --- |
| 汉字 | 字典中的每个读音；读音中的 v 同时产出 u；每个读音的首字母；汉字本身 |
| 连续字母（英文词等） | 整个词；词的首字母 |
| 数字 | 数字本身 |
| 空格、标点 | 跳过 |

例：

- `张` → `zhang`、`z`、`张`
- `曾` → `ceng`、`zeng`、`c`、`z`、`曾`
- `吕` → `lv`、`lu`、`l`、`吕`
- `Tom` → `tom`、`t`
- `9月1日 课堂表现` → `9` `yue/y/月` `1` `ri/r/日` `ke/k/课` `tang/t/堂` `biao/b/表` `xian/x/现`

### 2.2 自动机

- 每种写法的每个字符是一个状态；
- 同一写法内部按字符线性连接；
- 一种写法结束后，通过 ε 转移到下一个 token 的所有写法的首状态；
- 任意状态都可以作为查询起点（子串匹配），查询可以在某个音节中间结束；
- 查询每读入一个字符，只沿字符相等的状态继续；读完仍有活动状态即命中；
- 最后一个字符命中但状态没有后继时同样算命中。

复杂度为 `O(查询长度 × 状态数)`。状态数约为文本长度 × 每种写法的平均长度，**与多音字组合数无关**，因此没有变体数量上限。

### 2.3 归一化

查询与文本使用同一套归一化：

1. NFKD 兼容分解；
2. 去掉组合记号（声调、变音符等）；
3. 转小写；
4. 查询只保留字母、数字与汉字，去掉空格与标点。

因此：

- `zhāng`、`zhang` 等价；
- `lü`、`lv`、`lu` 都能匹配“吕”；
- `Müller` 与 `muller` 等价；
- 全角字母、数字会归一化为半角。

### 2.4 命中示例

| 文本 | 能命中的输入 |
| --- | --- |
| 张三 | 张三 / zhangsan / zhangs / zs / san / angs / 张s |
| 曾三 | zengsan / cengsan / zs / cs / 曾san |
| 吕雨 | lvyu / luyu / lü / lv / lu / ly / 吕y |
| 李雷2 | 李雷 / lilei / ll / 2 / lei2 / l2 / lilei2 |
| Tom李 | tom / tomli / tl / 李 / tli |
| 9月1日 课堂表现 | 9月 / yue1 / ktbx / 9y1r / 9yue1ri / 9月1日课堂 / 课堂 / ketang |
| Ｔｏｍ１２３ | tom123 / tom / 123 / t123 |
| Müller | müller / muller |

限制：

- 不支持跳过 token 的查询：`9月课堂` 不会命中“9月1日 课堂表现”，`李2` 不会命中“李雷2”。这是连续子串语义，不是多词搜索；
- 不支持拼写纠错（错别字、漏字母）；
- 匹配结果不做相关性排序，学生按表格显示顺序，记录/模板按数据顺序。

## 3. 模型与性能

- `SearchListModel` 只保存当前范围的条目：学生按 `displayOrder` 排序，记录/模板按数据顺序；
- 范围切换只重建条目，查询为空时直接显示全部，不构建匹配器、不运行匹配；
- 首次非空查询才为条目构建 `PinyinMatcher`，并在本次范围中复用；清空关键字不会丢弃匹配器；
- 拼音字典是进程级单例，首次真正需要汉字读音时加载一次（约 20–40 ms），此后所有范围共用；
- 学生页 ↔ 小组页切换不重建模型，成本为零；
- 数据变化只刷新当前范围：学生增删/排序/改名由表格模型的信号驱动（`MainWindow` 中转），记录/模板变化由 `ClassDataManager` 的 `recordsChanged` / `templatesChanged` 驱动；文件关闭时由 `MainWindow::resetTable()` 主动刷新。
- 只改小组号也会发出 `studentsChanged`，但不会改变可搜索文本，因此学生搜索不监听该信号，避免拖放分组时结果列表被重置。

按当前规模（几十名学生、几百条记录），每次按键全量匹配是微秒到毫秒级，不需要索引、缓存过滤结果或后台线程。若数据增长到上千条且首次输入出现可感知延迟，再考虑按范围缓存条目/匹配器或预建索引。

## 4. 字典

### 4.1 数据来源

- 仓库：https://github.com/mozillazg/pinyin-data
- 版本：v0.15.0
- 许可：MIT，Copyright (c) 2016 mozillazg
- 许可文件：`resources/pinyin-data-LICENSE.txt`
- qrc 路径：`:/pinyin/pinyin.txt`（文件位于 `resources/pinyin.txt`）

### 4.2 格式与统计

每行 `码点(4 位十六进制大写) 空格 音节[,音节]`，码点升序，文件头 5 行注释：

```text
4E00 yi
4E01 ding,zheng
66FE ceng,zeng
```

- 范围：U+4E00–U+9FFF；
- 20,924 个汉字；
- 27,317 个读音；
- 4,940 个多音字；
- 单字最多 8 个读音；
- 文件 216,412 字节；
- 读音已去调号，ü 记作 v；运行时同时生成 u 写法。

### 4.3 重新生成

1. 下载 v0.15.0 的 `pinyin.txt`；
2. 只保留 U+4E00–U+9FFF 的记录；
3. 每个读音做 NFKD，去掉组合记号与数字，转小写，ü→v，去重；
4. 写成 `码点 音节[,音节]`，并保留来源、版本、许可和格式注释；
5. 校验：20,924 行数据、27,317 个读音、4,940 个多音字。

数据变化后只需替换 `resources/pinyin.txt`，代码无需修改。
